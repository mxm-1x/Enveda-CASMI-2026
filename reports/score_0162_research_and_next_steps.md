# CASMI 2026: research and next steps after a 0.162 score

Research snapshot: 2026-10-02

## Diagnosis

The 0.162 result is consistent with a pipeline that mainly solves the public-spectrum retrieval slice and does little for molecules without reference spectra. It is not proof of the hidden test's class mix, but it is a strong diagnostic clue: a recent public reimplementation estimates the class-1 contribution at 0.162, and reports a library-only public score of 0.151. Its full four-channel system reached 0.328; another public analog-propagation notebook reports 0.335. These are leaderboard reports, not guarantees that the same score transfers to our run.

The original code had a capable reference-spectrum search and a COCONUT fragment reranker, but its blend preserved the spectral list and only appended database candidates into unused positions. Since the spectral route emits up to 25 candidates even when its evidence is weak, the database route was effectively shut out. That is consistent with, but does not prove, the 0.162 result coming mostly from the library-known slice. The local COCONUT fragment reranker by itself was limited; the mass-shifted analog channel is a much stronger database route.

The competition defines three cases: structures with reference spectra, database-known structures without spectra, and novel structures outside databases. It also says the visible `test.parquet` is a placeholder and the hidden set is substituted at notebook submission time. That makes validation by evidence ablation essential; visible-test overlap cannot select the model.

## Most promising method found

The public approaches that move from approximately 0.15 to approximately 0.33 use **candidate retrieval plus evidence fusion**, not free-form SMILES generation. Their useful channels are:

1. **Reference spectra**: retain our existing molecule-level library retrieval for the known-spectrum case.
2. **Mass-shifted analogs**: retrieve spectra from related compounds (roughly ±200 Da precursor neighborhood), then transfer evidence to a candidate using spectral similarity raised to a power and Morgan-fingerprint Tanimoto similarity. A public reimplementation reports class-2 MRR@25 around 0.47 for this channel alone.
3. **Structure fragmentation evidence**: score whether fragments generated by one- and two-bond cuts of a candidate explain the observed peaks. Our current scorer only models simple one-bond, non-ring, single-bond cuts, so this is a specific gap.
4. **Spectrum-to-fingerprint neural model (FPNet)**: predict molecular-fingerprint bit logits from the spectra and score candidates with their fingerprint dot product. Public solutions use supplied pretrained checkpoints; this is much better matched to the task than a general text SLM.
5. **Learned ranker**: combine the evidence channels candidate-by-candidate using the shared candidate-ranking training rows or leak-controlled local training. Do not hand-weight incomparable scores or reserve the database channel for empty slots only.

The public source repo describes a 712k-structure pool (COCONUT plus training structures), a ±10 ppm candidate window, scorer-equivalent tautomer/InChIKey14 de-duplication, and a gradient-boosted ranker over channel features. Its experiment notes also warn that fingerprint-model leakage can make validation look much better than real generalization. Candidate recall and holdout discipline therefore come before tuning fusion weights.

### Implemented local analog experiment

We added a streaming ±200 Da library scan and transferred each retrieved analog's evidence to mass-compatible candidates using `spectral_similarity^3 × Morgan-Tanimoto`. Validation excluded every raw library key mapping to a held-out target. On the separate 250-target natural-product holdout, COCONUT contained the truth for 248 targets. Analog-only achieved MRR@25 0.5197, hit@1 0.3508, hit@5 0.7379, hit@25 0.9315. On the shared candidate rows, the 10-feature fragment-only ranker scored 0.2638 MRR; the 15-feature fragment+analog model scored 0.5212 (about 1.98×), hit@1 0.3629, hit@5 0.7258, hit@25 0.9194. In molecule-grouped 5-fold OOF on 547 internal structures, fragment-only MRR was 0.4750 and multichannel MRR was 0.7961; this larger internal gain is optimistic and not a public-score forecast.

We changed the final Kaggle notebook to create fragment and analog features for COCONUT candidates, fit the 15-feature CPU ranker, and collect scorer-key-deduplicated spectral top-two diagnostics. A route switch is used because each prediction route fills all 25 slots. The initial threshold (spectral margin <0.03 => database route first) comes from source-vs-structure margin distributions: 12% of the 250 source-known targets and 45% of the 278 strict structure-held-out targets would go database-first. On the source-known slice, that switch lowers MRR from 0.9261 to 0.8938; on the strict structure slice, library-only MRR is zero, so the switch can help only if its analog/database candidate ranking transfers. This is a pragmatic class tradeoff, not a statistically calibrated novelty classifier. The margin distributions overlap and the threshold must be judged against new independent holdouts and the hidden Kaggle score.

## Recommended execution order

### 1. Validate route fusion on multiple external slices

The notebook now logs scorer-key-deduplicated spectral confidence and uses the threshold as a starting routing rule. Run the same route comparison on the independent 46-target COCONUT overlap slice and structure-held-out groups, and check candidate recall plus the ratio of database-first molecules. Change the threshold only if gains hold on multiple structure-disjoint slices.

### 2. Expand structure-aware fragment evidence

Extend the simple one-bond scorer to two-bond fragment explanations and evaluate it on the external COCONUT holdout and same-formula isomer panels. Keep each target structure excluded from all library-derived features.

### 3. Add a spectrum-to-fingerprint model only with a clean checkpoint

The public CASMI26 FPNet checkpoint is the next neural feature to research. Use it only if its training provenance confirms held-out molecules were not used to train that checkpoint; then compare its fingerprint logits on the local structure holdout before spending the 30-hour Kaggle GPU allowance. A generic text SLM is not appropriate for this numeric peak-ranking task.

### 4. Train and calibrate a multi-channel ranker

Train the ranker on molecule-grouped rows and evaluate leave-one-source-out or structure-disjoint splits. Report seed bands. Promote only changes that improve multiple holdouts, especially the database-known/no-spectrum slice. Assemble the final 25 by the scorer's tautomer-canonical key so aliases do not consume slots.

### 5. Add novel-structure enumeration only after the database route works

The current public evidence favors solving the database-known/no-spectrum route first. Public experiments report that simple database expansion and naive biotransformation enumeration did not reliably improve the leaderboard. Treat class-3 generation as a later experiment with strict local retention tests, not the first use of GPU hours.

## Model choice and compute

Do not start with a generic SLM. This is a structured numeric peak-list problem; the relevant learned target is a molecular fingerprint or a mass-spectrum embedding. The DreaMS paper and repository provide a pretrained transformer trained self-supervised on millions of tandem spectra, so it is a plausible later feature/analog-similarity experiment. The better first move is the CASMI-specific FPNet checkpoint already used in public solutions, because it predicts the exact candidate representation needed by this ranker.

Keep development and holdout evaluation on the Mac where feasible. Save the limited Kaggle GPU time for inference/feature extraction with the fingerprint network if it demonstrates local value, or for a controlled training run. The competition permits attached public data and pretrained models, but requires an offline notebook run under 9 hours; the public reference implementation reports an approximately 40-minute GPU run.
